# 磁盘 I/O 优化

## 改动

- 运行日志保留当前日期的文件句柄，在内存中合并 JSONL 记录，每 2 秒或累计 64 KiB 写入一次，正常退出时刷新剩余记录。日期切换时先刷新旧文件，再打开新文件。
- 日志目的地不可写时保留待写记录以便重试，待写缓冲上限为 256 KiB；超过上限的新记录按尽力记录策略丢弃，避免无限占用内存。
- 配置保存对每个文件只读取一次，同一份 JSON 用于有效性检查和变更比较；整个批次检查通过后，只原子替换有变化的文件。所有文件已存在时，每次保存由 16 次文件内容读取降为 8 次。
- 桌宠移动、滚轮缩放共用现有的 350 ms 延迟保存定时器；相同设置不重复写入。页面销毁和停止软件时仍立即保存。

## 本地对比

在 Windows Release 构建中，以修改前的日志和配置保存实现为基线，用相同测试程序执行：

1. 创建完整配置及一个副本。
2. 修改副本位置并保存 100 次。
3. 写入 2000 条日志，每条包含序号和 200 字符的内容。

通过 Windows `GetProcessIoCounters` 在各阶段前后取差值：

| 指标 | 修改前 | 修改后 | 降幅 |
| --- | ---: | ---: | ---: |
| 配置读取请求 | 3200 | 1600 | 50% |
| 配置读取字节 | 401956 | 200978 | 50% |
| 日志写入请求 | 2000 | 11 | 99.45% |
| 日志写入字节 | 662890 | 662890 | 0% |

上述数据是固定负载的进程 I/O 计数，包含操作系统缓存路径，不等同于物理磁盘读写次数或实际游戏场景的整体吞吐量。日志批处理主要减少小块写入和文件打开、关闭开销，不压缩日志内容。异常退出可能丢失尚未刷新的记录。

## 验证

新增测试覆盖日志缓冲、并发记录完整性、切换日志目录前刷新、写入失败后重试、桌宠重复设置不写入、连续位置变化合并保存和销毁前保存。原有配置损坏保护和未变更文件不重写的测试继续适用。

测试临时目录需可写；桌宠通知集成测试使用本机回环 HTTP 服务，启动冒烟测试使用本地单实例套接字，因此需要允许本机通信。
