# 桌宠 AstrBot 消息推送

“摸鱼桌宠”页的“提示与 AstrBot 推送”可将图色条件的提醒文案发送到自己的私聊或群聊。桌宠气泡与 AstrBot 推送分别开关，默认保留桌宠提示、关闭 AstrBot 推送。两种渠道共用每条规则的触发文案；留空则都不提示。推送无需上传头像或启用桌宠，运行模式也可在设置页选择。

## 三种运行模式

右键桌宠可选择下列模式，始终有且只有一个模式被选中，默认“常驻模式”。选择会保存并在下次启动恢复。

| 模式 | 小窗与划线 | 图色动作 | 桌宠文字 | AstrBot 推送 |
| --- | --- | --- | --- | --- |
| 常驻模式 | 按原设置显示 | 按原规则执行 | 允许 | 禁止 |
| 摸鱼模式 | 隐藏 | 暂停，仅检测提醒条件 | 允许 | 允许 |
| 勿扰模式 | 隐藏 | 暂停 | 禁止 | 禁止 |

“允许”的提醒渠道仍遵循各自的配置开关。模式不会清空开关、密钥、规则或小窗的显示偏好。摸鱼模式只检测当前启用槽位的规则条件，从不满足变为满足时提醒一次；不播放音频、不弹出小窗、不闪烁、不自动切屏、不跳转槽位、不增加规则触发次数，也不执行高级逻辑序列。勿扰模式停止检测提醒条件，切换时立即收起已有文字。离开摸鱼模式会取消尚未完成的推送请求，已经被服务器接受的消息无法撤回。

“禁用桌宠”下方的“停止软件”会保存配置、停止后台任务并退出整个程序，即使开启了保留到托盘也会退出。

## 配置

1. 部署 **AstrBot 4.18.0 或更新版本**，连接好需要接收消息的平台机器人。
2. 在 AstrBot WebUI 的“设置 → OpenAPI”中创建 API Key，授予 **`im`** scope。
3. 在接收消息的私聊或群聊向机器人发送 `/sid`，复制返回的完整 **UMO**（`平台 ID:消息类型:会话 ID`）。仅填写 QQ 号或用户昵称不能替代 UMO。
4. 在 EVE-Viola“摸鱼桌宠”页填写服务地址（默认 `http://127.0.0.1:6185`）、API Key、接收会话 UMO。支持 HTTP/HTTPS 地址、反向代理路径前缀，也可直接填写完整的 `/api/v1/im/message` 或 `/api/v1/im/messages` 地址。
5. 切换到“摸鱼模式”，点击“发送测试消息”，在目标会话确认收到消息，再开启“通过 AstrBot 发送触发提示”。测试按钮在自动推送关闭时也能使用；常驻、勿扰模式中不可发送。
6. 为需要提醒的图色规则填写文案。实际触发时发送 `账号名：文案`；没有账号名时只发送文案。

这里的服务地址是 **AstrBot 管理后台（WebUI）的地址**；若 AstrBot 与桌宠运行在同一台电脑且使用默认端口，可填写 `http://127.0.0.1:6185`。远程部署时填写桌宠能够访问的 AstrBot 地址。API Key 也必须在 **该 AstrBot 实例的“设置 → OpenAPI”** 中创建。

模型提供商的 Base URL 和密钥用于 AstrBot 调用大模型，不能用于桌宠主动消息推送。例如 `https://llm.example.com/v1` 这样的模型服务地址，应保留在 AstrBot 的模型提供商配置里。桌宠推送已有提示文案无需调用大模型。

设置自动保存在 `cache/desktopPet.json` 的 `astrBot` 对象中；`localMessagesEnabled` 保存桌面气泡开关，`mode` 保存运行模式（`resident`、`fish`、`doNotDisturb`）。API Key 在界面中遮蔽，但以明文保存在本机配置文件中。分享缓存前请删除 API Key；远程部署时建议使用 HTTPS。

## 发送行为与排查

- 同一账号、同一规则默认 30 秒内最多请求一次，可调整为 0–600 秒；0 表示不限制。不同账号或规则独立计时，桌面气泡不受冷却影响。失败请求也参与冷却。
- 请求异步执行，最多同时进行 4 个请求，总时限 10 秒。遇到 `404` / `405` 时会尝试一次另一版本的消息接口路径；其他错误不重试、不排队。失败或繁忙会在页面显示原因，不影响桌面提示。关闭自动推送阻止后续触发发送，已经发出的请求仍可能完成。
- `401`：身份验证失败。先确认地址是 AstrBot 管理后台地址、密钥来自该实例“设置 → OpenAPI”，再检查密钥是否完整或已被撤销。不要填写模型服务的 Base URL、模型密钥或管理后台登录密码。
- `403`：请求被拒绝。确认 OpenAPI API Key 已授予 `im` 权限；若经过反向代理，也检查代理的访问限制。
- `404` / `405`：检查 AstrBot 版本、服务地址和反向代理路径。
- AstrBot 返回失败、平台离线或目标 UMO 错误：检查 AstrBot 日志、平台连接和 `/sid` 返回值。
- 连接失败或超时：检查服务是否运行、端口和网络是否可达。
- 界面“已接受”表示 AstrBot 接口接受了请求，最终送达仍取决于消息平台。部分平台不支持主动消息。

常驻模式的桌宠文字沿用图色触发链路，被高级逻辑消除的效果不显示文字。摸鱼模式使用独立的条件边沿检测生成文字和推送，不执行图色动作与高级逻辑序列。

## 接口

程序默认请求 `POST /api/v1/im/message`，并兼容新版 REST 路径 `/api/v1/im/messages`，携带 `Authorization: Bearer <API Key>` 和 JSON：

```json
{
  "umo": "platform:FriendMessage:session_id",
  "message": [{ "type": "plain", "text": "Alpha：条件已经满足" }]
}
```

参考：[AstrBot HTTP API](https://docs.astrbot.app/dev/openapi.html)、[API Scope](https://docs.astrbot.app/dev/openapi-scopes.html)、[内置指令 /sid](https://docs.astrbot.app/use/command.html)。
